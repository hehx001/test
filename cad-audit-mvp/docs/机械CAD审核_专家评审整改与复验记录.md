# 机械CAD图纸审核项目：专家评审整改及复验记录

**整改依据**：《机械CAD审核项目评审》（2026-11-07），对应提交 \`2ef22979b892ef4e7cc9d2e65154616eba665c4f\`。  
**开发分支**：\`feat/mechanical-cad-audit-mvp\`；[PR #1](https://github.com/hehx001/test/pull/1)。  
**工作性质**：工程规则可靠性整改，保留原有DXF／BOM／STEP能力，不将程序规则的通过视作整机设计批准。

## 一、五项P1修订结果

| 问题 | 处理内容 | 可复现测试 |
|---|---|---|
| 尺寸系数和显式单位未参与比较 | 新增dimension_rules.py，根据DIMENSION类型、有效DIMLFAC、单位及可识别的显示精度比较；复杂或不能解释的标注列为未核验，不计为已验证相符。此处比对的是尺寸对象的定义测量，不代表与独立边/孔的关联已经确认。 | 100×DIMLFAC2→200相符；写100不符；100mm写100in不符；毫米与英寸等物理长度相符 |
| 零件编号被压缩 | 字段标签标准化与零件身份判断分别实现，编号只删首尾空格，保留连字符、下划线及大小写；材料仅进行保守的文字比对。 | AB-12、AB1-2、AB_12严格区分 |
| 开放壳体得到不合理体积 | step_safety.py先检测真实SOLID及其壳体封闭状态，体积仅汇总符合条件的SOLID；开放壳体不再进入实体体积判断。 | 开放壳体不产生STEP-001，闭合方块仍计算150 |
| 布尔运算失败直接忽略 | 每组包围盒候选都记录success、failed或not_supported，保存零件实例路径及诊断信息；报告列出计算成功数、失败数、未支持数及包围盒排除数。 | 故障注入IsDone=False产生STEP-003 |
| 模型回复被全部拒收仍报告成功 | 只接受引用本次实际送审规则与实体的有效事项；全部拒收显示invalid，部分有效显示partial，概述和核查范围由程序统计生成，不直接使用模型的合格断言。 | 错误概述、虚构实体、空对象、顺序导致重要STEP被遗漏 |

**判断范围**：可确认的是规则程序在上述受控条件下行为正确。尺寸文本与几何相符，不证明标注已关联到真实被标注边、孔或其他功能特征。

## 二、P2修订结果

| 问题 | 处理情况 |
|---|---|
| 部分图块实体转换失败未保留 | 使用ezdxf的skipped_entity_callback记录原因与原始引用路径，保留局部异常证据；实际未展开范围由DXF-006记录 |
| 嵌套图签未采集 | 递归读取实际引用的INSERT属性，并保存布局、图签实例路径；缺少图签或编号时产生未完成事项，不把不同图签合并成一个虚构对象 |
| 多重插入只检查首个实例 | 对MINSERT通过multi_insert枚举全部实例，给实例建立不同路径 |
| 模型只接收前20项 | 按STEP、跨文件、DXF、BOM等工程类别轮流选择，记录总数、送审数、未送审数、有效解释数及拒收数 |
| 大量多段线使预览异常 | 服务端单次预览最多5000个点，记录简化数量；浏览器计算边界采用循环；即使图形显示失败仍保留报告下载 |
| 非法端口造成服务失败 | 将URL解析错误转换为可控制的配置异常；模型调用失败不使已有工程规则记录丢失 |
| 未说明哪些检查完成 | 记录DXF检查范围、STEP配对状态、BOM跨文件完整性及上传文件SHA-256 |
| 非可信CAD解析缺少隔离 | DXF及STEP审查在独立子进程执行，采用时间限制，Linux另设CPU时间上限；解析失败和超时保留已有有效记录。**该措施并非生产级操作系统沙箱，尚无完整内存配额及容器防护。** |

## 三、验证资料和回归机制

- 项目既有基础检查、模型接口模拟测试、服务端密钥配置测试均保留。
- 新增\`tests/test_review_regressions.py\`，覆盖P1与P2问题的受控反例；150000顶点的完整DXF压力测试已在此前GitHub Actions实际执行通过，日常测试使用25000顶点样本，完整测试可设置\`CAD_STRESS_TEST=1\`单独执行。
- 新增\`tests/test_preview.js\`，采用Node/V8执行网页中的实际绘图函数，直接验证150000顶点数据不会触发此前的数组参数限制问题。

## 四、尚未具备的能力

1. **原生CAD几何关联审核**：尚未实现针对关联边、孔、轴线的完整尺寸校核。当前程序仅能校验DIMENSION自身的显示数值和定义点，并在结果中声明不支持进一步关联确认。
2. **完整工程设计包与独立专家答案**：公开样本适用于兼容性与部分规则验证，不能说明真实机械设计缺陷召回率。后续需要取得真实机加工安装板或支架的二维原件、三维装配、BOM、技术要求、修订记录和已签认错误。
3. **装配合理性**：静态实体交集仍是待确认的几何事实，不具备运动全过程、制造与装配间隙、合理过盈、强度与寿命判断能力；STEP文件实际长度单位尚未经过跨模型验证，不能将不明确的体积单位直接写成mm³。
4. **大模型独立视觉审查**：Qwen／DeepSeek当前只接收部分规则事项、证据摘要，并辅助解释；不接收CAD原文件或图纸局部图片，不独立执行几何测量，也没有自动调用专业几何工具。
5. **生产级安全**：目前仅适合授权的本地试验，不支持完整的操作系统隔离、生产审计、共享权限及外部公网部署。

## 五、下一阶段明确安排

建议选取一种常见安装板或支架的小装配，取得30—50套相互独立、专家签认的设计包作为试点基础。优先检验：
- 标注与关联边、孔、中心距是否一致；
- 图号、材料及版本与正式BOM是否一致；
- 装配体是否存在非预期穿透或规定间隙不足。

基于同一批图纸，将“规则可确定检查”“需要视觉语义提取”“需要工程条件确认”分开测试。对于模型，先进行局部图纸信息识别评测，再决定是否开放视觉API；不能以当前文字解释模块的质量代替几何设计判断。

质量验收应分别报告解析完整性、规则精确率与召回率、证据定位正确率、未完成比例以及设计工程师复核耗时。所有改动仍保留在草稿PR，不自动合并主分支。
